Multi-tenant

Chaque organisation = 1 realm Keycloak. TenantFilter extrait le realm du JWT → TenantContext (ThreadLocal UUID). Toutes les requêtes JPA filtrent par tenant_id.

Résilience LLM

Groq primaire. Sur 5 échecs / 10 appels → circuit ouvert resilience4j → bascule immédiate OpenAI gpt-4.1-mini. Refermeture 30s. SSE broadcast via Kafka (group-id unique par pod ${HOSTNAME}).

Contexte du mois

Pourquoi Gouvernance IA & Sécurité maintenant ?

Après la consolidation technique de Juillet, Août est consacré aux deux axes non-fonctionnels les plus critiques avant d'aller en production réelle : la gouvernance des modèles IA et la conformité réglementaire RGPD. Ces sujets ne peuvent pas être traités en fin de projet — ils structurent la confiance des clients ESN.

Risque réglementaire : Sans audit trail LLM et sans mécanisme de droit à l'oubli, la plateforme ne peut pas être vendue à des ESN opérant sous contrat avec des grandes entreprises (banques, assurances, secteur public) qui exigent ces garanties contractuellement.

PII Masking — règles à appliquer

  • Emails : remplacer par [EMAIL] avant envoi LLM
  • IBAN/BIC : remplacer par [IBAN]
  • Noms propres : remplacer par [NOM] (via NER ou regex)
  • Numéros de téléphone : [TEL]
  • Adresses IP : [IP]
  • Le prompt masqué est loggué — pas l'original
  • Le prompt_hash = SHA-256(prompt_original) pour audit sans exposition

Token Budget par tenant

  • Table tenant_token_budget : budget_mensuel, tokens_consommés, alerte_seuil
  • Alerte à 80% du budget → notification admin platform
  • Blocage à 100% → HTTP 429 "Budget LLM épuisé"
  • Reset automatique le 1er du mois
  • Dashboard platform_admin : consommation par tenant en temps réel
  • Default budget : 500 000 tokens/mois/tenant

User stories Sprint 3

  • En tant que platform_admin, je consulte un dashboard montrant la consommation LLM (tokens, coût estimé, latence p95) par tenant et par mois
  • En tant que DPO, je certifie qu'aucun email, IBAN ou nom propre n'est transmis aux APIs LLM externes (Groq/OpenAI)
  • En tant que platform_admin, je fixe un budget de tokens mensuel par tenant et reçois une alerte quand 80% est atteint
  • En tant qu'auditeur, je peux exporter le log de tous les appels LLM d'un tenant sur une période donnée (format CSV)
  • En tant que consultant, si le budget LLM de mon organisation est épuisé, je reçois un message explicite (pas une erreur 500)

Model Versioning & Incident Response

  • Table llm_model_registry : model_id, provider, version, deployed_at, deprecated_at, replacement
  • Rollback automatique si un modèle génère >5% d'erreurs JSON en 10 min
  • Runbook "LLM Incident" : détection → confinement → rollback → post-mortem
  • Alerte PagerDuty (ou équivalent) si fallback Groq→OpenAI dure >15 min
  • DPIA (Data Protection Impact Assessment) rédigé et validé DPO
  • Registre des traitements mis à jour
  • Politique de rétention des données : logs = 90j, données métier = 7 ans (légal)
  • Chiffrement AES-256 at-rest sur les colonnes sensibles (IBAN, token LLM)
