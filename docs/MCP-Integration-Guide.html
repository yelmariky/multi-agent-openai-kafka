Vue d'ensemble

Ce que fait ce serveur MCP

Ce serveur expose, via le protocole MCP, un accès en lecture seule aux notes de frais et factures d'un tenant IA-INSIGHT. Il permet à un système externe (agent IA, outil de reporting, ERP tiers…) de consulter ces données de façon standardisée, sans avoir à intégrer l'API REST propriétaire de la plateforme ni à gérer un flow d'authentification Keycloak complet.

Aucune mutation possible. Cette première version ne permet ni de créer, ni d'approuver, ni de modifier ou supprimer quoi que ce soit. C'est un choix de conception délibéré : un canal externe sans utilisateur humain qui confirme dans une interface présente un risque plus élevé pour des opérations d'écriture — on commence par la consultation.

Les 4 outils exposés

OutilDescriptionParamètres
list_expenses Liste les notes de frais sur une période, avec filtres optionnels. startDate, endDate, consultantEmail?, type?, approvalStatus?
get_expense_summary Résumé agrégé d'un mois : totaux Personnel/Business, répartition par statut. month (YYYY-MM)
list_invoices Liste les factures sur une plage de mois, avec filtres optionnels. startMonth, endMonth, clientCompanyName?, consultantEmail?
get_invoice_status Détail et statut de paiement d'une facture précise. invoiceName (ex: F-202610-01)

Connexion

Comment se connecter

1. Obtenir une clé API

Chaque tenant dispose d'une clé API dédiée, à demander à l'administrateur de la plateforme IA-INSIGHT. Cette clé est unique, rattachée à votre organisation, et révocable à tout moment sur simple demande — sa compromission n'affecte que votre propre tenant.

2. Paramètres de connexion

URL de basehttps://<votre-domaine>
TransportSSE (Server-Sent Events) — standard MCP historique
Endpoint de connexionGET /sse — ouvre le flux, renvoie l'URL de session à utiliser pour les appels
Endpoint des appelsPOST /mcp/message — envoi des messages JSON-RPC (URL exacte fournie par le flux SSE)
En-tête d'authentificationX-MCP-Api-Key: <votre_clé> (sur les deux endpoints)
Ne pas tester avec un simple curl ponctuel. Le transport SSE nécessite de maintenir la connexion GET /sse ouverte pour récupérer l'URL de session, puis d'envoyer les appels POST /mcp/message sur cette même session — ce n'est pas un simple aller-retour HTTP. En pratique, ce protocole est géré automatiquement par les SDK MCP (Python, TypeScript) et par tout agent compatible MCP : il suffit de leur fournir l'URL de base et l'en-tête d'authentification.

3. Vérifier la connexion — MCP Inspector

L'outil officiel pour tester interactivement un serveur MCP, sans écrire de code :

npx @modelcontextprotocol/inspector

Dans l'interface qui s'ouvre (http://localhost:6274), configurez :

  • Transport : SSE
  • URL : https://votre-domaine/sse
  • En-tête personnalisé : X-MCP-Api-Key: <votre_clé>

Vous verrez la liste des 4 outils, pourrez remplir leurs paramètres dans un formulaire et exécuter les appels un par un.

4. Exemple d'appel — lister les notes de frais de septembre 2026

Une fois la session SSE établie par votre client/SDK, le message JSON-RPC envoyé est :

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_expenses",
    "arguments": {
      "startDate": "2026-09-01",
      "endDate": "2026-09-30",
      "approvalStatus": "APPROVED"
    }
  }
}

Sécurité

Modèle de sécurité

🔒 Isolation par tenant

Chaque clé API est rattachée à un seul tenant. Toutes les requêtes sont automatiquement filtrées par organisation — une clé ne peut jamais accéder aux données d'un autre tenant, quelle que soit la requête envoyée.

📖 Lecture seule stricte

Aucun outil exposé ne modifie de données. Toute la logique de lecture réutilise exactement les mêmes services que les consoles admin/consultant — aucune divergence possible entre ce que vous voyez via MCP et via l'interface web.

⏱ Limitation de débit

Chaque clé API est limitée à un nombre de requêtes par minute configurable côté plateforme (30/min par défaut). Au-delà, les requêtes sont rejetées avec un code 429 jusqu'à la minute suivante.

📝 Journalisation

Chaque appel d'outil est journalisé côté plateforme (nom de l'outil, tenant, clé masquée) pour permettre un audit en cas d'usage suspect.

Codes de réponse

CodeSignification
200Requête traitée avec succès
401Clé API absente ou invalide
403Organisation désactivée
429Trop de requêtes — limite de débit atteinte
Révocation. En cas de compromission suspectée d'une clé, contactez l'administrateur de la plateforme pour une révocation immédiate et l'émission d'une nouvelle clé — l'opération ne prend que quelques minutes et n'affecte pas les autres tenants.
