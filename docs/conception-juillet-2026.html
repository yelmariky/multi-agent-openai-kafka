Section 2

Solution proposée & Périmètre

Vision produit : Une plateforme SaaS multi-tenant d'automatisation administrative pour ESN, propulsée par des LLM open-source (Groq) avec pipeline RAG sur pgvector. L'utilisateur parle à un assistant IA en français naturel — il s'occupe du reste.

✅ Dans le périmètre

  • Notes de frais — saisie libre, OCR, frais km
  • CRA mensuel — workflow BROUILLON→SOUMIS→VALIDÉ
  • Congés CP/RTT — demandes & solde
  • Facturation — PDF & Excel client
  • Notifications SSE temps réel
  • Pipeline RAG pgvector + LLM Groq/OpenAI
  • Multi-tenant Keycloak realm-per-tenant
  • Gouvernance IA (audit, PII masking, token budget)
  • Conformité RGPD (droit à l'oubli, portabilité)
  • AWS Production (EKS, RDS, MSK, DR)

Multi-tenant — realm-per-tenant Keycloak

Chaque organisation cliente dispose de son propre realm Keycloak. Le TenantFilter extrait le realm depuis le claim iss du JWT et positionne le TenantContext (ThreadLocal UUID) avant tout accès JPA. Toutes les requêtes DB filtrent par tenant_id.

Résilience LLM — Circuit Breaker

Groq est le LLM primaire (500 tok/s, gratuit tier dev). En cas de panne, resilience4j circuit breaker détecte 5 échecs sur 10 appels et bascule immédiatement sur OpenAI gpt-4.1-mini, sans délai de retry. Le circuit se referme après 30s.

S1

Consolidation architecture & Kong routing complet

Semaines 1-2 · Juillet 2026 · Responsable : Tech Lead Backend

Objectif du sprint

Terminer proprement la décomposition microservices initiée en Juin : retirer le code métier dupliqué de ai-service, configurer Kong pour router vers les bons services, et valider la non-régression end-to-end.

User stories

  • En tant que Tech Lead, je retire tous les controllers expense/CRA/leave de ai-service afin qu'il ne reste que les modules settings, organization, RAG et reasoning
  • En tant que consultant, mes appels /expenses/* et /cra/* passent par Kong vers les bons microservices sans régression fonctionnelle
  • En tant qu'admin, le dashboard charge ses données depuis les bons services via Kong sans modifier le frontend
  • En tant que DevOps, je dispose d'un script de smoke-test automatisé validant tous les endpoints critiques après déploiement

Livrables techniques

  • Suppression controllers expense/CRA/leave de ai-service (src + tests)
  • Kong declarative config : /expenses/* → expense-service, /cra/* → activity-service, /leaves/* → activity-service, /notifications/* → notification-service
  • Mise à jour config.js des 3 frontends (apiBase via Kong)
  • Script smoke-test.sh (curl sur 15 endpoints critiques)
  • Mise à jour docs/ENDPOINTS.md
  • Mise à jour CLAUDE.md (routing actuel)

S2

UX Design System & cohérence 3 frontends

Semaines 3-4 · Juillet 2026 · Responsable : Tech Lead Frontend + UX Designer

Objectif du sprint

Unifier l'expérience utilisateur des 3 consoles (admin, consultant, platform) sur une base de composants cohérente, accessible (WCAG 2.1 AA) et responsive. L'objectif n'est pas un redesign complet mais une harmonisation et l'élimination des incohérences visuelles.

Inventaire composants à harmoniser

frontend/ (Admin :3000)
Composants : Dashboard KPI, queues d'approbation, tableau frais/CRA, drawer settings

Problèmes : Boutons primaires incohérents, pas de skeleton loader, tableau non responsive
frontend-consultant/ (:3001)
Composants : Saisie libre, upload OCR, CRA grid mensuel, congés

Problèmes : Mobile cassé sur CRA grid, liste absences volumineuse (résolu S0), loading LLM absent
frontend-platform/ (:3002)
Composants : Gestion tenants, provisioning organisation

Problèmes : Page minimale, manque feedback actions, pas de confirmation destructive

User stories UX

  • En tant que consultant sur mobile (iPhone 14), je peux remplir et soumettre mon CRA sans scrolling horizontal ni éléments tronqués
  • En tant qu'utilisateur, je vois un skeleton loader animé pendant les appels LLM (3-30s) plutôt qu'un écran figé
  • En tant qu'admin, chaque action destructive (suppression, refus) déclenche une modale de confirmation avec le libellé de l'entité
  • En tant qu'utilisateur malvoyant, tous les éléments interactifs ont un ratio de contraste ≥ 4.5:1 (WCAG AA)
  • En tant qu'utilisateur clavier, je navigue dans l'app sans souris (Tab, Enter, Escape fonctionnels)
  • En tant que consultant, la page "organisation introuvable" est stylée comme le reste de l'app (déjà livré)

Livrables

  • shared/design-tokens.css — variables CSS centralisées, importées par les 3 frontends
  • Skeleton loader (.skeleton-pulse) pour les appels LLM et chargements lents
  • Composant Modal de confirmation réutilisable (JS pur)
  • CRA grid : responsive mobile (grid → stack sous 768px)
  • Toast notifications harmonisées (succès/erreur/info)
  • ARIA labels sur tous les boutons icône et champs complexes
  • Audit contraste : rapport accessibilité pour les 3 frontends
  • Breakpoints définis : 320px / 768px / 1024px / 1440px
