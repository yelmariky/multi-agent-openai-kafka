## Post #11 — Chiffre choc : le DSO des ESN (page)

**Format :** texte court + visuel chiffre
**Cible :** dirigeants ESN

```
Le délai moyen de paiement d'une facture en France : 44 jours.
Mais dans le conseil IT, le compteur démarre souvent 15 jours
APRÈS la fin de mission.

Pourquoi ? Le circuit infernal :
fin du mois → relance CRA → validation → saisie facture → envoi
→ chaque étape ajoute des jours.

15 jours de retard de facturation sur 100 consultants à 550 € TJM,
c'est ~800 000 € qui dorment en permanence hors de votre trésorerie.

La solution n'est pas de relancer plus fort.
C'est de supprimer les étapes :
CRA validé = facture générée = facture envoyée. Le même jour.

C'est exactement ce qu'on a construit avec IA-INSIGHT.

Votre DSO, vous le connaissez ? Il est à combien ? 👇

#ESN #Trésorerie #Facturation #DSO
```

## Post #18 — Stack technique complète (page)

**Format :** texte tech + schéma d'architecture
**Cible :** tech/IA, CTO

```
Notre stack complète pour un SaaS B2B multi-tenant, en toute
transparence 🔧

Backend :
→ Java 21 + Spring Boot, architecture microservices
→ PostgreSQL 16 + pgvector pour le RAG (index HNSW)
→ Kafka pour l'événementiel (notifications temps réel, découplage)
→ Keycloak : un realm par client = isolation forte des identités
→ Kong API Gateway en frontal

IA :
→ Groq (llama 3.1 / llama 4 scout) en LLM principal — rapide, gratuit
→ Fallback OpenAI automatique via circuit breaker
→ OpenAI text-embedding-3-large pour les embeddings
→ Tesseract pour l'OCR des reçus

Infra : Kubernetes, CI/CD GitHub Actions avec tests de
gouvernance IA à chaque build (scan anti-injection inclus).

Les choix dont on est le plus contents :
1. pgvector plutôt qu'une base vectorielle dédiée (simplicité)
2. Realm Keycloak par tenant (sécurité démontrable en avant-vente)
3. Le fallback LLM (zéro incident visible côté client)

Des questions sur un de ces choix ? On développe en commentaire.

#Engineering #Java #Kubernetes #IA #SaaS
```
