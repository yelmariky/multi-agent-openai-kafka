Vision produit : Plateforme SaaS multi-tenant d'automatisation administrative pour ESN. L'utilisateur parle à un assistant IA en français naturel — il s'occupe du reste.

Multi-tenant

Chaque organisation = 1 realm Keycloak. TenantFilter extrait le realm du JWT → TenantContext (ThreadLocal UUID). Toutes les requêtes JPA filtrent par tenant_id.

Résilience LLM

Groq primaire. Sur 5 échecs / 10 appels → circuit ouvert resilience4j → bascule immédiate OpenAI gpt-4.1-mini. Refermeture 30s. SSE broadcast via Kafka (group-id unique par pod ${HOSTNAME}).

User stories Sprint 5

  • En tant qu'admin, après validation d'un CRA, je vois une notification "Générer la facture pour {consultant} — {mois}" dans mon dashboard
  • En tant qu'admin, je génère la facture en 1 clic — les données seller sont pré-remplies depuis le profil, je complète uniquement le client et le TJM si absents
  • En tant qu'admin, je marque une facture comme "Envoyée" et la date d'envoi est enregistrée automatiquement
  • En tant qu'admin, je marque une facture comme "Payée" avec le montant reçu — l'écart par rapport au montant facturé est calculé
  • En tant qu'admin, je reçois une alerte 30 jours après l'envoi si la facture n'est pas encore payée
  • En tant que platform_admin, je consulte le chiffre d'affaires total par tenant et par mois

Livrables techniques

  • InvoiceScheduler.java : job @Scheduled quotidien vérifiant les factures non payées à J+30
  • Invoice statuts : BROUILLON → ENVOYÉE → PAYÉE | ANNULÉE
  • Endpoint PATCH /invoices/{id}/mark-sent (date_envoi)
  • Endpoint PATCH /invoices/{id}/mark-paid (montant_reçu, date_paiement)
  • Dashboard admin : liste factures par statut + indicateurs CA mensuel
  • Notification SSE "Facture en attente de génération" post-validation CRA
  • Export comptabilité : CSV factures par période (pour comptable externe)

Definition of Done — Sprint 5

  • Workflow complet testé : CRA validé → facture générée → envoyée → payée (parcours E2E)
  • invoiceDate = 1er du mois suivant le CRA (test unitaire)

  • Scheduler relance : déclenché en test avec délai artificiel, alerte SSE reçue
  • Export CSV comptabilité : format validé par un comptable (test d'acceptation)

Dashboards Grafana à créer

  • Platform Overview : SLA uptime, req/s, erreurs 5xx, CPU/RAM par pod
  • LLM Intelligence : latence par modèle, tokens/min, coût estimé, taux fallback, taux d'erreur JSON
  • Business KPIs : notes de frais créées/jour, CRA soumis/validés, factures générées/payées
  • Kafka Health : lag consumer, throughput, partition distribution
  • Alertes Prometheus : pod restart > 3/h → CRITICAL, latence p95 > 1s → WARNING
  • Log format JSON unifié : timestamp, level, service, tenant_id, trace_id, message
  • Corrélation logs → traces → métriques (Grafana Explore)
  • Retention : métriques 30j, logs 15j, traces 7j

User stories Sprint 6

  • En tant que DevOps, je reçois une alerte Slack en moins de 5 minutes si un pod crashe ou si la latence LLM dépasse 5s
  • En tant que Tech Lead, je consulte sur Grafana la latence p95 LLM des 7 derniers jours ventilée par modèle (Groq vs OpenAI fallback)
  • En tant que platform_admin, je consulte le nombre de notes de frais créées par tenant sur le mois courant
  • En tant que DevOps, tous les logs des 5 microservices sont centralisés dans Loki avec trace_id permettant de reconstituer une requête cross-service
  • En tant que Tech Lead, je dispose d'un runbook pour chaque type d'alerte critique (pod down, DB connexions saturées, circuit breaker ouvert)
